## Purpose / Big Picture

Repair the three reproduced LMDB durability defects with root-cause storage and recovery changes, backed by RDF4J-native crash-recovery tests. Preserve the independent full-payload oracle and distinguish process death from simulated sudden storage loss: killing only a Java child does not discard the host kernel or storage cache. A power-loss result is valid only when the database is on a faulted guest filesystem backed by a device model that truthfully implements completed FLUSH/FUA durability.

The test oracle must be independent of the database and live outside the crash target. It records commit intent, explicit rollback, commit invocation, and durable acknowledgments. For acknowledged transactions A, recovered committed transactions C, commits with unknown outcomes U, and explicit rollbacks R, require `A ⊆ C ⊆ A ∪ U`, require `C ∩ R = ∅`, require each unknown transaction to be fully present or absent, and freeze resolved unknown outcomes across later restarts. Verify full RDF payloads, not just transaction markers or counts, then check latest mutable state, deletion non-resurrection, and public access paths.

## Context and Orientation

`core/sail/lmdb` stores RDF statements in `TripleStore`, value IDs and quoted terms in `ValueStore`, and namespace prefixes in a separate `NamespaceStore` file. An RDF repository commit crosses these storage components, so a recovery test must verify logical RDF transactions and public reads after reopening the entire repository. `LmdbStoreConfig.setForceSync(true)` is mandatory for the acknowledged-commit durability claim; when false, LMDB uses weaker sync flags. Test fixtures should exercise namespaces, typed and language-tagged literals, blank nodes, quoted triples, default and named graphs, deletes, rollback, resize/growth, and retired-value cleanup where those features are part of the chosen history.

The external witness is a separate append-only file held outside the LMDB directory and forced after each acknowledged commit. Let A mean a commit response was durably recorded before the cut, U mean the commit was invoked but its outcome was not durably acknowledged, C mean the transaction's complete audit payload is recovered, and R mean an explicit rollback or an operation whose commit was never invoked.
