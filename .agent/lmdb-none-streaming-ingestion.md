## Purpose / Big Picture


An explicitly begun `IsolationLevels.NONE` transaction should ingest arbitrarily long RDF streams without keeping the whole stream in a Java model or a temporary replay file. Ordinary per-statement adds should receive the same sorted, aligned LMDB writes as the existing bulk writer. Native transactions will be committed in bounded chunks when their work budget or either map's configured fullness threshold requires it, while the public repository transaction stays active. A later rollback may leave already committed chunks, as the existing NONE contract permits, but dictionary IDs, triples, namespaces, notifications, readers, and estimators must remain consistent.

## Context and Orientation


The public transaction is the transaction a user begins on `RepositoryConnection`. A native transaction is one LMDB writer handle inside either the `values` or `triples` environment; those environments cannot commit atomically together. A native chunk is bounded work committed dictionary-first and triples-second while the public NONE transaction remains active. A batch is a smaller array of quad components submitted through the optimized triple writer; many batches can belong to one chunk.

`core/common/transaction/src/main/java/org/eclipse/rdf4j/common/transaction/IsolationLevels.java` states that NONE sees its own changes but may not roll them back and guarantees no isolation. `core/sail/base/src/main/java/org/eclipse/rdf4j/sail/base/SailSourceConnection.java` creates transaction branches only for stronger levels and carries read/order/flush barriers. `core/sail/lmdb/src/main/java/org/eclipse/rdf4j/sail/lmdb/LmdbStoreConnection.java` supplies connection-owned NONE sources, tracks write attempts, admits paired readers, and publishes connection events.

`core/sail/lmdb/src/main/java/org/eclipse/rdf4j/sail/lmdb/LmdbSailStore.java` owns the common writer, an asynchronous TripleStore worker, publication scopes, namespace snapshots, and value-retirement processing. `LmdbSailSink.addStatement` is the ordinary per-row path; `approveAllBulk` and `BulkAddQuadsOperation` are the existing aligned path. `TripleStore.java` implements aligned per-index sorting, cursor reuse, native commits, and replay; `ValueStore.java` implements dictionary IDs, refcounts, lazy-value associations, native writer ownership, and dictionary commit. `TxnManager.java` manages native readers; untracked pinned readers survive commit and actual resize invalidates their binding. `MapGrowthPolicy.java` computes soft fullness and hard reserve. `TxnReplayPolicy.java` and `TxnMutationJournal.java` represent the existing atomic transaction replay policy, which must remain intact for stronger levels.
