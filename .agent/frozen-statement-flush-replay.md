## Purpose / Big Picture


An LMDB transaction should retain its complete logical statement changes until native commit succeeds. If a native write attempt exhausts map capacity, the store can abort that attempt, grow the affected native map under the shared admission gate, and replay the retained changes from the beginning without allocating a statement journal. This also makes large buffered transactions safe under memory pressure: estimation and replay traverse closeable cursors rather than copying every statement into lists. Existing direct writers, internal spill stores, namespace-only transactions, and the NONE checkpoint path retain their existing recovery behavior.

Users can observe this through commit-and-reopen integration tests with additions, removals, clears, explicit and inferred statements, namespaces, injected capacity failures, and constrained heap. Covered transactions must succeed without creating a `TxnMutationJournal`; direct-writer journal tests must still run and pass. Failed or cancelled attempts must leave no partial publication or duplicated callbacks.
