## Purpose / Big Picture


An LMDB transaction should retain its complete logical statement changes until native commit succeeds. If a native write attempt exhausts map capacity, the store can abort that attempt, grow both related maps, and replay the retained changes from the beginning without allocating a statement journal. This also makes large buffered transactions safe under memory pressure: estimation and replay traverse closeable cursors rather than copying every statement into lists. Existing direct writers, internal spill stores, namespace-only transactions, and the NONE checkpoint path retain their existing recovery behavior.

Users can observe this through commit-and-reopen integration tests with additions, removals, clears, explicit and inferred statements, namespaces, injected capacity failures, and constrained heap. Covered transactions must succeed without creating a `TxnMutationJournal`; direct-writer journal tests must still run and pass. Failed or cancelled attempts must leave no partial publication or duplicated callbacks.

The complete carrier state model is as follows. The transient prepared carrier P belongs to the interval between source preparation and flush; the persistent SERIALIZABLE carrier S belongs to the original admitted read boundary and can remain present after ordinary flush clears P. P and S can be the same object. A source with neither role validates captured observations through its eventual backing carrier. A source with P only validates P and retires it after acknowledgement. A source with S only still validates S, even if its local capture is empty. A source with both validates each distinct identity once; a shared P/S is never released or closed twice. Every one of these four role combinations permits empty, statement, or observation-only local work. Local emptiness does not imply that an ancestor prefix or original validation history is empty.

Freezing retains exact model generations and their immutable mutation barriers, leaving original writer aliases separate from carrier roles. Enlisting registers all existing P/S identities throughout a composite before logical transfer. Staging copies each suffix's observations into each distinct original validation carrier, validates external history, and releases Changeset preparation reservations before forwarding models. A newly discovered ancestor registers its carriers before any history prepend. All graph-owned carriers are excluded from own-graph history publication; unrelated pending carriers receive the exact incoming generation. A later appended suffix repeats observation validation against the original ancestor carrier without repeating earlier model transfer or publication. Native validation carriers, including Memory's original-snapshot sink, retain their writer exclusion until the whole physical application finishes.

A confirmed acknowledgement first seals captured generations and removes exactly those entries. P is retired. S is renewed only when its own or inherited model generation was sealed; observations and history move before retiring the old carrier, and the new sink is admitted at S's original requested isolation level rather than overwritten generation metadata. The same renewal helper runs before later preparation or frozen staging because ancestor-only acknowledgement can seal a descendant S without invoking a descendant batch callback. Original public writer aliases always remain sealed. Cancellation releases preparation ownership and removes only internally staged copies, preserving original models, observations, and history for rollback or ordinary use.
