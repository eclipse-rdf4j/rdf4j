### Legacy identity and policy publication: design constraints

The documented format-2 contract preserves the original `store.properties` bytes through a no-op open, writes and reopen. The existing store UUID is a durable logical ownership identity; it is not by itself a certificate that both native environments or a particular snapshot are current. Any auxiliary identity must provide no stronger authority than that existing receipt. Independently retain the existing native-generation and snapshot-freshness proofs wherever the consuming capability requires them, and reuse those proofs instead of inventing a cross-environment protocol merely for a stable UUID. The following is the required state table, not an assertion that the implementation already exists:

| Observed state | Required action |
| --- | --- |
| Admitted old pair, no identity receipt, no actual language migration | Preserve the original policy bytes. Derive no persisted estimator authority until a generation-bound identity has been durably established; memory-only estimation remains permissible. |
| Identity publication interrupted before all required owner receipts are durable | Never publish or adopt persisted feedback from the partial state. Preserve its evidence and resume or safely decline only after authenticating the current native pair; a stale intent alone cannot authorize a replaced component. |
| Matching durable identity and applicable freshness receipts | Admit a persisted result only under its existing ownership and freshness contract. A matching UUID alone cannot substitute for native-generation or exact-snapshot authority where those are independently required; an old writer or unrecorded change must follow the existing invalidation/rebuild contract. |
| Missing, malformed, foreign, mismatched, or partially replaced receipt | Do not adopt, overwrite or delete an unowned artifact. Decline persisted authority or establish a new independently authenticated generation without reusing stale feedback. |
| Real language migration completes, with property publication interrupted or completed | Recover the migration using its native ownership and completion proofs. If an identity is written into the policy during a legitimate migration, it must agree with the already established durable owner; a no-op does not manufacture a policy change. |
| Fresh, modern, prepared, standalone, or explicitly supplied format authority | Preserve the existing admission, native-generation, marker and publication contracts; never infer a missing modern capability from a legacy fallback. |

Before production edits, preserve a first-red plus controls for authentic no-op reopen with and without estimator persistence, interrupted identity publication and retry, an actual language migration, an actual old-writer cycle, and foreign/replaced native components at the existing admission boundary. Validate directory/file forcing, ownership on concurrent or repeated startup, and the relevant freshness requirements separately from UUID equality.
