## Purpose / Big Picture

After this change, a user can expand a stored blank node, search by its fixed reference, filter by it, inspect annotations, discover links, and send it from classic Workbench pages to the graph. A fixed reference is RDF4J's `<_:id>` query operand: it names a node in one repository. Ordinary `_:label` is an allocation or document label and never grants this capability. Stored nodes returned by SELECT and CONSTRUCT must remain usable; freshly allocated, imported and remote result labels must remain displayable without acquiring repository authority.

## Surprises & Discoveries

The existing `RdfTerm.scope` belongs to a result document or a query batch, not a repository. `AbstractSPARQLJSONWriter` currently emits only a blank-node label. `RemoteBNode` has trusted in-memory provenance, but ordinary result serialization discards it. `BNodeIdResolver` checks a value dictionary, and MemoryStore registers freshly created values there, so dictionary existence after query evaluation cannot establish stored-node authority.

Unicode decoder parity matters: Java rejects individual surrogate scalar escapes and raw lone surrogates, accepting literal supplementary pairs or a valid eight-digit scalar escape. The frontend initially missed that distinction; a regression now covers parity and decoding once. `crypto.randomUUID` is secure-context-only, which would break ordinary HTTP Workbench imports. Result document identity now uses a 128-bit `crypto.getRandomValues` session nonce and a document counter, with an import regression where `randomUUID` is absent.

Playwright's configured Chromium revision was absent, and sandboxed installed Chrome initially failed with macOS Mach-port permission errors. Retrying the existing installed browser outside the sandbox succeeded without installing dependencies. This enabled four actual rendered failing regressions before any App/details/preferences edits, followed by four passing regressions after the edits.

Canonical Find had a second root cause: the seed query scanned only outgoing triples, so a stored resource occurring only as an object appeared absent. A real-repository test failed with one expected row versus zero. The generalized seed now scans independently anchored source and target UNION branches, with DISTINCT and the existing 100-row limit. Controls cover incoming-only, outgoing-only, mixed edges and self-loops across default, all, IRI-named and blank-named scopes. In all-scope tests RDF4J's default view may already include named statements; the additional GRAPH branch can therefore repeat a statement. Label search's outer projection now uses DISTINCT after a failing two-versus-four-row semantic test exposed that duplication. The bound-source connection query intentionally also returns type resources; only the discovery consumer intersects target IDs with loaded nodes, so the new Java scan assertion was corrected to include its third rdf:type row.

## Context and Orientation

`tools/workbench/src/main/frontend/graph-explorer/rdf-terms.ts` owns SPARQL JSON terms and graph IDs. `rdf-vocabulary.ts` builds bound-resource queries and graph scopes. `rdf-explorer.ts` batches and keys metadata results. `GraphExplorerApp.tsx` chooses which nodes controls may query. `statement-details.ts`, `link-counts.ts`, `facet-queries.ts`, and `graph-connection-discovery.ts` build related queries. `graph-additions.ts` reads the repository-scoped classic handoff queue. The classic writer is `tools/workbench/src/main/webapp/scripts/ts/graphAdditions.ts`; callers are in `queryStream.ts` and `workbenchViews.ts`. Backend graph queries run in `tools/workbench/src/main/java/org/eclipse/rdf4j/workbench/commands/GraphServlet.java` through repository connections, often HTTPRepository connections. Server-side protocol and core evaluation therefore matter to provenance.

An authority grant is backend evidence that a particular result value is a reusable identity in the connected repository, not merely that its raw label happens to occur there. The new JSON extension and its parser must retain that evidence only through trusted repository transport. The implementation must handle recursive RDF 1.2 triple terms, whose syntax is `<<( s p o )>>`; `<< s p o >>` is reifier syntax and must not be parsed as a triple term.
