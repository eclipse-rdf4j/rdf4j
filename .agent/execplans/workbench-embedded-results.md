# Embed Workbench Query Results Below the Editor

This ExecPlan is a living document and follows `.agent/PLANS.md`. It records the implementation, discoveries, decisions, and verification for embedding Workbench query results below the query editor while preserving the existing result renderers, paging, downloads, and cancellation behavior.

## Purpose / Big Picture

After this change, executing a non-empty query keeps the Workbench query page in place. The editor, actions, and separate explanation controls remain visible; the result appears below them in a same-origin iframe. A new execution clears the previous result and shows loading, and a cancel action stops only the result request while leaving the editor usable. Tuple, graph, boolean, error, empty, paging, and download responses continue to use the existing XML/XSL pipeline and result controls.

## Surprises & Discoveries

- The current same-tab implementation sent short executions through `document.location` and long executions through the editor form (`tools/workbench/src/main/webapp/scripts/ts/query.ts`); both paths must be redirected without changing save/explain behavior.
- Result templates all include `transformations/template.xsl`, whose root template emits the complete Workbench shell (`tools/workbench/src/main/webapp/transformations/template.xsl:13-140`). A metadata-gated fragment branch is safer than a URL-gated branch because only QueryServlet responses will emit the new marker.
- Pagination forms generated in `tools/workbench/src/main/webapp/scripts/ts/paging.ts:92-126` do not carry a request ID. Embedded pagination therefore needs a fresh ID and a parent start notification for cancellation.
- Attachment responses are selected by `QueryServlet.setContentType` (`QueryServlet.java:898-932`) and do not produce an XSL result marker. Downloads must remain fire-and-forget from the parent lifecycle so loading state cannot remain stuck.
- A failed iframe navigation does not reliably fire `iframe.onerror`; a same-origin `load` can still expose a response without the result marker. Inspecting the loaded document marker and current location is therefore required for both HTTP failures and malformed XML responses. Evidence: `e2e/query-result-lifecycle-browser-red-followup.log` failed before the repair and `e2e/query-result-lifecycle-browser-final-green.log` passes after it.
- The initial `about:blank` load and attachment responses have no result marker. They must be ignored or treated as completed only when no render request is active; otherwise they can clear a newer request or leave a download stuck. Evidence: `e2e/embedded-browser-live-followup.log` records `DOWNLOAD suggested=query.nt status=""` and a subsequent successful request.
- The narrow viewport inherits the existing fixed Workbench sidebar, so its content column remains constrained by the legacy shell. The query-scoped frame now sizes from content up to a 640px cap, while the embedded result surface owns horizontal table scrolling; this keeps short results compact without redesigning the unrelated shell. Evidence: `design/workbench-query-refresh/implementation-narrow.png` and `e2e/query-refresh-layout-green-final4.log`.
- The first full module attempt was blocked only by sandbox socket restrictions in five proxy utility tests. Rerunning the exact `mvnf` module command with external socket access passed all 441 tests; no source change was made for that environment failure. Evidence: `workbench-module-final.log` versus `logs/mvnf/20260923-125537-verify.log`.
- A late iframe error can arrive after explicit Cancel has cleared the active ID. Failure handling now ignores markerless frame errors when no render is active, preserving the explicit `Query cancelled.` status. Evidence: `e2e/query-cancel-late-error-red.log` failed before the guard and `e2e/query-cancel-late-error-green.log` passes after it.
- Blank request metadata must be classified before stale-ID comparison. Otherwise a terminal embedded document with an empty marker ID is treated as stale and leaves the parent cancellation state active. Evidence: `e2e/query-review-red-node.log` failed for both GET and long POST harness paths; `e2e/query-review-green-node.log` passes both.
- Embedded paging controls can outlive the editor's mutable cookies. Query text, language, inference, timeout, and the visible result limit therefore come from the rendered result marker/DOM; standalone pages retain their cookie-based form construction. Evidence: the cookie-drift assertions in `e2e/query-review-green-node.log` and the metadata assertion in `logs/mvnf/20260923-131140-verify.log`.
- Anonymous live Workbench sessions render the Save-private checkbox disabled, while the Save query disclosure and save action remain usable. The final smoke records `private-enabled=false` and a successful `Query saved.` response instead of changing authentication defaults.
- A local MemoryStore live smoke run returned HTTP 404 for cancellation because its short request completed before the delayed browser response could keep the coordinator handle active. The parent still stopped the iframe and reported `Query cancelled.`; the evidence labels the endpoint result as an already-completed local-fixture limitation.
- The graph renderer's existing table shape exposes one table row for the constructed result in this fixture, so live graph coverage asserts the table and embedded limit request rather than imposing tuple-specific tbody row counts.
- `setResultLoading(false)` is called during the initial `pageshow` lifecycle event. Making it unconditionally show the result section exposed a blank island before Execute; visibility now changes only for loading/status/result state, and lifecycle restoration explicitly clears and hides the panel.
- Workbench shell action rules have higher specificity than the explanation stylesheet's unscoped cancel rule. The primary Explain cancel wrapper now uses shell-scoped aria-state selectors so an `aria-hidden="true"` wrapper cannot render as a ghost red icon-only action.
- The optional Node coverage wrapper has a pre-existing red baseline (HEAD archive: 90.34% lines, 82.54% branches, 93.66% functions against 100% thresholds) and is absent from `.github/workflows/*`; the current 88-test run remains red without any threshold/exclusion changes.

## Decision Log

- Decision: Use a fresh iframe DOM identity for each top-level Execute, while keeping a stable iframe `id`/`name` for the new request. Rationale: removing the old frame clears previous results and makes late `postMessage` events fail both source and request-ID checks. Date/Author: 2026-09-23, Codex.
- Decision: Use a temporary POST form targeted at the result iframe for long queries. Rationale: mutating the editor form target risks redirecting Save or Explain; a temporary form isolates execution submission. Date/Author: 2026-09-23, Codex.
- Decision: Add a small parent/child protocol. `rdf4j-query-start` adopts a fresh ID for embedded pagination; `rdf4j-query-result` completes or fails that ID. The parent accepts messages only from the current same-origin iframe and ignores blank, stale, or wrong-source messages. Date/Author: 2026-09-23, Codex.
- Decision: Add `workbench:embedded` metadata in `QueryEvaluator.addWorkbenchMetadata` for tuple, graph, and boolean XML results; add it directly in QueryServlet error and empty branches. Rationale: those branches do not share one builder path, while the XSL root can safely select fragment output from the marker. Date/Author: 2026-09-23, Codex.
- Decision: Keep `Accept` download forms outside the parent active-render lifecycle and retain native attachment handling. Rationale: attachments intentionally have no XSL completion marker; stopping their iframe remains a transport disconnect fallback. Date/Author: 2026-09-23, Codex.
- Decision: Treat a nonblank iframe `load` without the current result marker as a terminal frame failure when a render is active, while ignoring initial `about:blank`, stale frames, and markerless downloads when no render is active. Rationale: browser iframe error events are not dependable for HTTP 500/plain-text/malformed responses, but a load with no current marker must not leave cancellation state stuck. Date/Author: 2026-09-23, Codex.
- Decision: Stop only the result iframe during `pagehide`, `pageshow`, and explicit Cancel, then clear the active ID; report `Query cancelled.` for explicit user cancellation. Rationale: leaving the parent document and explanation requests usable while preventing uncancellable result work is the accepted lifecycle contract. Date/Author: 2026-09-23, Codex.
- Decision: Route every embedded graph limit and paging action through a fresh ID/start notification, regardless of whether its preceding response came from GET or POST; preserve `Accept` downloads outside that protocol. Rationale: a completed GET-origin result otherwise reused a dead ID and bypassed cancellation. Date/Author: 2026-09-23, Codex.
- Decision: Use the shared request-ID generator from `template.ts` in the parent and result-side scripts, with no production fallback counter in `query.ts`. Rationale: one generator prevents divergent ID behavior and lets test harnesses load the real helper. Date/Author: 2026-09-23, Codex.
- Decision: Embedded form options use `data-query-language`, `data-query-infer`, and `data-query-timeout` metadata plus the displayed query text and `limit_query` control; an embedded limit change supplies one explicit override and never appends the old visible value. Standalone form builders keep their existing cookie behavior. Rationale: the editor and explanation controls remain mutable while a result is displayed, and ordinary servlet parameter lookup can read the first duplicate limit. Date/Author: 2026-09-23, Codex.
- Decision: Empty embedded query responses carry the current request ID and `completed` result status just like normal and error responses. Rationale: the parent must be able to settle an empty execution through the same frame lifecycle. Date/Author: 2026-09-23, Codex.
- Decision: Render embedded responses as complete HTML documents with the Workbench shell omitted. Rationale: iframe navigation and accessibility are more robust with explicit `html`, `head`, and `body` nodes while duplicate navigation/editor/footer remain absent. Date/Author: 2026-09-23, Codex.
- Decision: In embedded output, internal Explore links target the parent; external URL links retain `_blank`. Rationale: a full Explore page should not appear inside the result frame, while existing external-link behavior is unrelated to query execution. Date/Author: 2026-09-23, Codex.
- Discovery: The generated JavaScript must be regenerated before Node harness tests can exercise the TypeScript changes; `tools/workbench/compileTypescript.sh` updates the four edited script/map pairs. Date/Author: 2026-09-23, Codex.
- Decision: Scope the refresh through the query page wrapper, embedded result body class, and query stylesheet loaded only by query templates; use `:has(#query-page)` for the legacy shell so other Workbench pages keep their existing global layout. Rationale: the current shared shell has no page-specific body class, and this keeps the responsive change local without adding a framework. Date/Author: 2026-09-23, Codex.
- Decision: Treat an iframe load with an XML document lacking a document element as an intermediate browser XSLT transition and wait for the document lifecycle event; classify concrete markerless documents as failures and preserve stale nonempty IDs. Rationale: Chromium emits a markerless XML load followed by the valid HTML document at 390px, while plain-text and malformed responses expose terminal documents. No grace timer is used. Date/Author: 2026-09-23, Codex.

## Design Refresh Scope

The visual refresh is intentionally limited to the query page and the embedded result document. Keep the existing RDF4J header, navigation, repository context, query execution/cancellation behavior, explanation controls, result paging, term links, and native downloads. Use scoped query-page CSS and the existing XSL structure; do not introduce Tailwind or another runtime dependency and do not globally restyle unrelated Workbench pages.

Baseline findings from the retained Chromium screenshots (`e2e/embedded-results-desktop.png` and `e2e/embedded-results-narrow.png`): the page still inherits the legacy body gradient and default form controls, the result panel repeats dense gray gradients and small controls, the desktop has excessive unused vertical space below a short result, and the narrow viewport exposes the existing fixed sidebar/header overflow. The redesign uses a slate canvas, white islands with restrained shadows, readable type, deliberate spacing, dark-slate primary actions, blue links/focus, and the existing orange RDF4J logo accent. Embedded result scrolling is bounded inside the result surface; the narrow shell constraint is handled locally rather than by a global mobile redesign.

The next design cycle is ordered as: root-generated visual prototypes, selected restrained direction, deterministic query-page/result wire diagrams, scoped XSL/CSS implementation, then browser and interaction verification. No production UI files are changed until the prototype and wireframe decisions are recorded here.

Final audit is limited to the query lifecycle sources/generated assets, XSL/CSS, Java metadata routing, focused tests/harnesses, and retained evidence/plan artifacts; no branch, commit, push, or unrelated cleanup was performed.
