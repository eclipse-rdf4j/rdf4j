## Purpose / Big Picture

People exploring RDF data should be able to choose which languages and label predicates name resources, relationships, and types. The graph will use the browser's ordered language preferences initially and the existing common RDF naming vocabularies. Users can reorder, add, and remove both kinds of preference, and changes survive reloads. A small notice guides people when loaded labels have several naming conventions or when their configured choices do not match the loaded labels. Dismissing guidance is remembered separately for each server and repository.

## Surprises & Discoveries

Newly accepted private-use/grandfathered language tags exposed an existing fallback error: `x-local` truncated to the dangling singleton `x`, incorrectly matching unrelated `x-other` before a later preferred `en`. A separate valid long private-use range also made unbounded depth exceed the numeric rank bucket and overtake the next language. Both smallest tests failed before the correction. Remove dangling singleton subtags when truncating and encode depth as a bounded fraction within its language's bucket. This preserves the user's language order for every supported tag length, while retaining ordinary regional, untagged, and wildcard behavior. The singleton rule was checked against RFC 4647 section 3.4.

The initial asynchronous integration waited for schema discovery before applying already-successful label metadata. A controlled rendered regression loads only relationship/type statements, then changes the predicate policy while holding schema discovery pending; it failed because `Alice RDFS` remained absent despite a completed successful label query. Apply successful labels immediately, while keeping negative guidance incomplete until both operations settle. Preference captions based on generic IRI compaction also collapsed 21 default predicates into 15 distinct captions. Use vocabulary-qualified preference captions, distinguish HTTP and HTTPS schema IRIs, and retain full custom IRIs; graph human labels remain prefix independent. The Java priority matrix originally compared an exact `nb` label with a regional `nb-NO` label, accidentally mixing language matching and property ordering. Both fixtures now use `nb-NO`, and a separate assertion preserves exact-language-before-regional semantics.

Observation aggregation now collects all valid loaded candidates per resource and merges once per resource, preserving direct and indirect paths without repeatedly copying growing evidence arrays for each edge. The outer persisted cache is already bounded by bytes; no additional 4096-element evidence threshold is necessary. The exact seven-test observe selection passed before this neutral refactor and must pass afterward.

The existing explorer ranks languages first, then a fixed vocabulary list. Additional properties are alphabetically sorted in the cache namespace and do not influence ranking. The language panel already reorders languages but additional properties cannot be reordered or removed and do not persist. Recreating the explorer can treat the preceding explorer's rendered label as a supplied label, losing its provenance. The graph does not fetch repository namespaces; its compact identifier captions use a fixed known-prefix list, while readable labels use literals or humanized IRI local names.

## Context and Orientation

The React application is `tools/workbench/src/main/frontend/graph-explorer/GraphExplorerApp.tsx`. It creates an `RdfExplorer` in `rdf-explorer.ts`, which collects literal candidates from loaded edges and bounded SPARQL metadata queries. `rdf-vocabulary.ts` generates these queries and selects labels. `label-preferences.tsx` renders the drawer controls. `graph-types.ts`, `graph-terms.ts`, and `graph-operations.ts` carry parsed RDF terms into graph objects.
