## Surprises & Discoveries


The maintenance opener's `upgradeStore()` returns true without migration and the caller relabels any differing version as2. Supported v6 must bypass that entire flow. Historical StoreProperties setters overwrite the dirty bit, so normal configured repositories can lack store.properties. That valid legacy path cannot be replaced by the optimized branch's blanket nonempty-directory rejection.

Format6 bulk/fresh dictionary writers may reuse the same ordinal across different reference families. A core-literal ID additionally embeds six datatype-tag bits above its ordinal. Legacy first-free-ID recycling and last-physical-key recovery are therefore unsafe for v6. Garbage collection is also semantically visible: searchable RDF-star term indexes feed TripleRef evaluation. Append-only/no-GC is excluded because it can expose removed terms and is not a complete general solution.

Direct adjacency and value-overlay generations live in process memory and are rebuilt on reopening. Hash cache files are compatible; normal per-ID maintenance is required. Persisted join/filter statistics and native cost learning can outlive a maintenance mutation and need owned freshness handling if their learners are bypassed.
