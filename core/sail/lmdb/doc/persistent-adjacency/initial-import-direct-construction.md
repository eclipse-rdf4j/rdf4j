# Direct construction for the first explicit NONE import

The initial-import owner already retains sorted statements until both the dictionary and statement environments have completed their native commits. This change keeps that owner, its retry protocol and its incomplete-import marker. It changes only how that owner's empty statement generation is built.

Previously the merge called the ordinary single-statement mutation path. Each distinct statement wrote two edge deltas and repeatedly adjusted native metadata; commit then rewrote the deltas into pages and deleted them. The full Theme workload exposed this as sustained single-core insertion followed by a much longer deletion/compaction pass, rather than an observed lock deadlock.

## Construction and boundaries

The collector prepares PSOC and POSC streams, ordered by raw unsigned IDs. The explicit outgoing and incoming streams are consumed sequentially. Each writes final pages of at most 1,024 pairs, with no edge deltas or dirty/candidate directories. Row and predicate counts are emitted once per completed group. Context totals and ID-role reference incidences are reduced through a 16,384-key partial map and retained sorted spills. A shared ID contributes once for every role it occupies; the default graph 0 contributes to context counts but not to references.

Before any page is written, the same native writer must contain no pages, no deltas and exactly the existing valid format certificate in metadata. A logically empty generation with old pages or tombstones is rejected. This is not an overwrite/reindex/migration path. Inferred writes, later NONE writes and the separate bulk-loader retain their existing paths.

Both directions must have the same distinct count, and each stream must be strictly unsigned ordered. The same collector owns both source streams; count equality is not represented as a cryptographic proof that arbitrary independently supplied files contain the same set. Reduction records require the exact kind, reserved field, positive weight and nondecreasing group order. Owned count overflow is reported as storage failure; arbitrary derived callback exceptions retain their identity.

Derived statement events are recorded once from the outgoing stream, preserving fan-out maintenance and current-revision in-memory adjacency rebuild/invalidation. No empty delta is invented for a nonempty load. The method does not commit, resize, retry or remove the import marker. Its private scratch directory closes before any capacity error returns to the existing owner. The dictionary's concurrent run files and retained canonical statement runs are never cleaned by that private helper.

Final merges have at most 32 input file handles; a consolidation group uses at most 33 including its output. Consolidation preserves duplicate records, since deferred dictionary lookups must diagnose duplicate keys rather than silently discard them. Owned read/write buffers are heap buffers rather than accumulated GC-managed direct buffers. File-name bookkeeping still scales with the number of runs, and provisional input buffering remains governed by the existing NONE checkpoint owner; this is not a claim of constant total heap for arbitrary unsupported inputs.

## Evidence and limits

A deterministic 4,096-quad fixture, duplicated across actual retained spill runs, has 8 final pages and 332 non-format metadata keys. Before the change it performed 8,192 delta puts, 8,192 delta deletes, 67,596 metadata puts and 67,722 metadata point gets. Direct construction writes the 8 pages and 332 metadata keys once each, with zero delta/dirty work and constant metadata admission checks. Exact live and cold-reopened statements are checked before the work assertions.

Independent model tests cover all metadata bytes/counts, both directions and four logical scan orders, long rows crossing page boundaries, default/named contexts, repeated ID roles, accepted raw high-bit object IDs, duplicate runs, old-authority refusal, and an initially empty in-memory index becoming an exact populated current-revision index.

Same-machine A–B–B–A measurements use fresh stores, Java 25, a 1 GiB heap, two active processors, forceSync=false, identical generated statements and exact live/cold models. The 550K-input sample contains 549,994 distinct statements. Frozen compiled production JARs and the identical harness are retained with hashes in task evidence. The final, coherently tested implementation (JAR SHA-256 `54b29e30d793f5d1307ce98c3127519b4992501ec499f5a73333d0f4e38868f3`) measured mean final commit 7.058→1.609 seconds and setup/input-to-exact-adjacency-ready 12.418→7.033 seconds, two forks per version. An earlier implementation snapshot measured 6.506→1.772 and 11.513→7.915 seconds respectively; that earlier snapshot predates the final merge lifetime/cancellation corrections. Post-commit adjacency waiting alone was longer in both direct samples; the reported total includes that wait. These small paired samples are not a full-scale throughput guarantee or a durability-mode comparison. They certify direct adjacency readiness, not separate value-overlay readiness. The full 14.77M Theme workload still requires post-fix CI validation.

A subsequent diagnostic of the earlier frozen sample produced identical final page and metadata entry counts between versions, and identical in-memory base bytes; that footprint diagnostic was not repeated for the final JAR. The direct metadata B-tree had approximately 6% more leaf pages, consistent with its changed insertion order but not a proven causal or timing attribution; sorted final metadata remains a separate potential optimization. Eight actual recovery/process-crash cases pass: outgoing/incoming page and final-reference capacity failures, a consumed final-commit capacity failure, terminal noncapacity failure, and three certified process-death boundaries. They verify retained inputs, closed cursors and private scratch before abort/remapping, actual native capacity growth, exact dictionary identities, both directions and cold reopen. Process death is not represented as a power-loss simulation. Four real file-channel/physical-merge controls also pass, including first-read cleanup, primary/suppressed exception identity, bounded duplicate-loop interruption and a measured 33-handle peak. The coherent Maven lifecycle compiled all production and test sources and passed 116 cases across 15 suites, with no failures, errors or skips. Full-scale post-fix CI remains separately pending; no full-Theme success is claimed.
