# Zero-length path binding origin

Native zero-length path evaluation distinguishes a query-term constant or true substitution from an ordinary runtime-bound variable. VALUES/inlined variables are not constants merely because `Var.hasValue()` is true. Their identity arm requires the term to occur as subject or object in the active graph/dataset and current explicit/inferred snapshot. Predicate-only and dictionary-only terms are not graph nodes.

The planner retains constant origin and per-endpoint substitution flags. A substitution exemption applies only when that endpoint is actually bound. Bound/bound endpoints must still denote the same RDF term. Original query constants and correlated EXISTS substitution retain store-free identity, including graph-absent terms. A general path with a potentially nullable step and a genuine constant/substitution endpoint conservatively retains generic evaluation before frontier renaming. This preserves legitimate absent-term identity through compound paths without misclassifying ordinary VALUES. Steps proven to require a statement stay native. API-origin general paths likewise decline before rewriting. The structural step analysis covers parser-generated connected paths; arbitrary programmatically constructed, disconnected ALP subtrees are not a validated contract of this change. This correctness rule is independent of `rdf4j.lmdb.nativeZeroLengthNodeIds.enabled` and does not change the both-free ID-row producer.

Membership uses exact scoped existence probes for canonical stored IDs. Synthetic IDs are re-resolved against the canonical backing dictionary before probing; output bindings keep their original IDs. Legacy/noncanonical dictionaries instead use a scoped statement scan with RDF-term equality, because one alias ID's absence does not establish a term's absence. This correctness-first fallback can cost O(scoped statements) per bound identity. Every iterator/probe is closed on exhaustion, early match or failure; loops poll cancellation.

API-input-origin paths conservatively use the generic evaluator so lookup provenance is not erased by the ID-only bridge. Unbound graph variables retain their existing generic fallback. No membership cache, new store format, optimizer join rewrite, factorization or separate rollout switch is added.

`LmdbNativeZeroLengthValuesOracleTest` documents the independent exact-bag oracle. For data `:a :p :b`, `VALUES ?s { :a :a :missing } ?s :p? ?o` yields `(a,a)` twice and `(a,b)` twice—not an additional `(missing,missing)`. Separate tests protect constants, EXISTS, scopes, aliases, literals, inferred visibility, snapshots, API bindings and iterator ownership.
