## Purpose / Big Picture


Choose where a filter runs from the work that the query actually performs, while keeping the binding and scope correctness rules already repaired on GH-6066. A correlated EXISTS should run after a selective join when that avoids needless probes, before a join that multiplies the same input into many rows, and early when it rejects rows that would otherwise cause expensive downstream work. The implementation should compile all legal placements, evaluate the logical filter at one selected placement, and change that selection safely during execution. It must retain the current aggregate-placeholder/HAVING repair.

The observable success is equal complete result bags with much less repeated work in the ENGINEERING q4 and MEDICAL_RECORDS q5/q10 shapes. A result bag includes each binding row and its multiplicity; matching only the number of returned rows is insufficient. Runtime trials have a cost, so the design promises correctness, explicit learning limits, and useful adaptation when evidence is sufficient. It does not promise the globally fastest plan for every data distribution or every short query.

## Proposed Architecture


Create one shared, non-mutating placement enumerator in the evaluation optimizer package. Extract the semantic decisions already used by `FilterRelocator` into this component, so static movement and adaptive enumeration use the same scope, repeatability, binding-state and Extension rules. For each logical filter, assign a stable query-local id and produce alternatives describing the candidate site or set of sites and their condition-visible input frame. Enumerate both upward and downward from the current static placement: an early seed must still be able to discover a better late site. Existing mutation-oriented downward relocation is the source of semantic rules, not a ready-made symmetric enumerator. Do not use variable-name presence or the native required-slot mask as a substitute for these proofs.

Enumerate only after the final structural algebra and join-order rewrites, including filter-to-VALUES transformations. Keep the resulting envelope immutable for that plan generation; if a later rewrite is unavoidable, invalidate and rebuild it before execution. Resolve candidate sites against the actual physical operators during precompilation, where the join implementation and binding layouts are known. This prevents stale node identities and a semantic alternative being mistaken for an implemented runtime adapter.

A logical placement may be a cut through several execution paths. For example, distributing an outer filter into UNION requires gates covering both arms. Selecting just one arm would lose filtering on the other. Store these cuts as placement alternatives; exactly one alternative is active for each logical filter. Within a selected UNION cut, each output path executes the logical filter once even though several physical gates participate. Preserve duplicates and the existing condition short-circuit/error behavior. If an adapter cannot establish a common drain boundary for a cut, that cut is static-only until an appropriate adapter exists.

Compile each safe execution site into a single gate bundle containing its relevant logical filter ids, compatible prepared conditions and shared arrival counters. Avoid allocating a wrapper for every filter/site pair. The bundle checks the region's immutable `PlacementVector`, which selects one alternative per logical filter. Inactive entries pass through without running the condition. The ordinary evaluator evaluates BindingSets; the native adapter evaluates RowState/slots. Both use the same controller policy and semantic envelopes. A logical condition has one semantic owner, but a prepared condition step may be shared only where `QueryEvaluationContext`, binding layout and scope are equivalent; otherwise prepare site-compatible steps under explicit ownership. Close their resources exactly once.

The vector belongs to one query execution or independently evaluated invocation, never to a shared algebra object, cached prepared plan, static map or another query's thread. It is fixed while a cohort is in flight. A boundary adapter reports completion only when every row produced by that cohort has been filtered, buffered rows cannot reappear under a different selection, and owned suffix iterators have drained or closed. Pending changes become the vector for the next cohort. A canceled or failed cohort produces no learning commit and cleanup closes all opened iterators. Existing rows and side effects are never replayed to test another placement.

Start with adapters for ordinary nested-loop regions and transparent deterministic wrappers, because these cover the reported medical/engineering shapes. Preserve the current physical join order and algorithms. Admit a physical adapter explicitly, rather than blindly wrapping every tuple step. Keep raw statement-pattern identities and guard capabilities available while `JoinQueryEvaluationStep` chooses its fast path; gates must neither disable these paths accidentally nor bypass a required condition. Unsupported guard paths remain static until a boundary-preserving adapter is tested. UNION children can initially remain opaque factors inside a region; this already permits placing q10's filter before versus after union fanout. Add branch-cut adapters as a separate composition milestone with exact bag tests. Scope-changing subqueries, hash/merge joins, GROUP, ORDER, DISTINCT, slices and effectful operators are boundaries unless their adapter proves a valid cohort protocol. This does not reject the whole query: safe regions inside or below a boundary remain eligible. Do not claim flat MultiJoin depths support arbitrary nesting.

Retain HAVING's statically proven movement through aggregate placeholders. Adaptation is unnecessary for an inert wrapper, and Group remains the semantic boundary. Actual assignments or volatile expressions continue to block illegal movement.

### Optional follow-up: demand-driven outcome reuse

For a filter whose complete condition-visible frame is proven stable from its own earliest legal anchor through a drainable suffix, allocate one outcome cell for that filter's current anchor cohort. Its states are unevaluated, accepted, rejected, or FILTER expression error. Evaluate only when the active gate first receives a demanded descendant, using that gate's correct condition frame; then reuse the outcome for the remaining descendants of that same anchor. No descendant means no evaluation. Reset the cell when the anchor cohort drains, and never reuse it for the next occurrence merely because it has equal correlation keys. This is constant retained state per live filter anchor, rather than a query-wide correlation-key cache; nested anchors require explicit ownership and lifetime, so it is not automatically one cell for an arbitrary compound region.

The prerequisite is the same kind of complete binding-state proof that permits earliest placement, made explicit across the memoized suffix: direct references, correlated inputs and EXISTS-local names, including unbound states, cannot change. The snapshot, dataset, inferred setting, outer invocation and condition context must also remain stable; operational failures propagate and abort the cohort. Cache an expression error only when ordinary FILTER evaluation would treat it as rejection. This proposed contract is stronger than merely observing the same selected depth or passing a required-name mask. Branches that introduce different frames cannot share an outcome cell.

With that proof, late placement becomes demand-only testing: ENGINEERING q4 still tests only the two demanded matches, while q10 can test once per demanded patient despite UNION expansion. q5 still needs early pruning to avoid observation work. Outcome reuse therefore complements adaptation rather than replacing it. Keep actual evaluation, memo-hit and rejected-descendant counters separate, and revise cost comparisons to charge actual execution. Validate fixed placements without reuse first, then compare the optional reuse layer independently; neither the native reference nor this design turn implements it.

## Measurement and Controller Policy


The objective is work for the whole region, normalized by its input cohorts, including rejected cohorts. Record predicate evaluations and failures, subquery cursor/probe opens and scanned rows, ordinary right opens and scanned/output rows, actual replay/materialization work, and sampled active execution time. Never normalize by accepted result rows: q5 accepts no input rows. Never replace invocation counts with distinct correlation-key counts unless the actual evaluator performs matching memoization. The first implementation adds no such memoization.

Use one inclusive regional active-time measurement as the elapsed objective, excluding time the consumer spends between calls. Predicate timing is an attribution/proposal measurement, not an extra term added to that inclusive total. Count work for deterministic policy tests and diagnostics, and sample timing outside tight per-triple loops to limit observer cost. The native `1/4/16` condition classes and `8` per-open weight may initialize proposals but must not be the acceptance evidence for arbitrary subqueries. Unsupported measurement must be explicit rather than a confident zero.

For a repeatable filter whose inputs are stable across a nested-loop suffix, the reasoning is:

    early(x) = predicateCost(x) + passes(x) * downstreamCost(x)
    late(x)  = downstreamCost(x) + downstreamRows(x) * predicateCost(x)

Sum over input row occurrences, including duplicates. The common prefix cancels. This is an explanation of the tradeoff, not permission to multiply independent marginal averages. In ENGINEERING q4, downstreamRows is nearly always zero because name matching rejects almost everything, favoring late testing. In q5, passes is zero and downstream work is substantial, favoring early testing. In q10, passes is one and downstreamRows exceeds one, favoring early testing. More complex operators are evaluated as complete execution alternatives, with their actual direction, frame and buffering semantics.

The controller seeds each region from existing static placement, using page counts and concrete finite scalar domains only when they supply valid information. It does not set `supportsJoinEstimation=true` or consume the page-only work/output stub as a real estimate. Page information can prioritize a trial; normal execution supplies the missing conditional evidence.

At a drained boundary, propose one candidate for one filter coordinate. Arrivals, observed rejection, fanout, active predicate time and total regional work guide prioritization, but a candidate can be tried even when the current late gate has no evaluations or very few. A zero arrival count downstream of an early reject-all gate is censored evidence, not proof that later placement is cheap. A late pass rate cannot be transferred to all earlier rows. Never execute predicates at inactive gates to fill those gaps.

Run a bounded trial on fresh cohorts with every other filter coordinate held fixed. Bracket trial windows with control windows at the current placement when enough work remains, so a changing input distribution is less likely to look like a placement benefit. Compare measured regional work/time per cohort, not two incomplete subtrees or projected output counts. Commit only repeatable improvements larger than measurement resolution and the controller's amortized overhead; otherwise restore the previous selection at a safe boundary. Reuse the native concepts of trial rollback, cooldown and increasing observation intervals. Do not transplant its 20% rejection/90% pass eligibility rules as facts about arbitrary data. Explain the selected placement and learning cost in runtime telemetry.

One query-level learning budget limits trial starts, extra observation work, timing samples and concurrent experiments. Overlapping regions serialize their experiments; disjoint regions may adapt independently if their work accounting is not double-counted. Keep the full legal envelope and rotate eligible candidates/filters fairly within this budget, instead of permanently selecting only the native highest-score filter. Short or low-work queries may finish at their seed placement.

There is a necessary budget limit: a controller that changes placement only after a cohort drains may overshoot its trial work budget by the currently in-flight cohort. An arbitrarily expensive subquery or arbitrarily large fanout has no universal constant bound. Strict trial-loss caps require a proven per-cohort bound before admitting a trial or additional lineage/epoch machinery for safe mid-cohort changes; that machinery is outside this first design. Query cancellation/deadlines still take effect normally. Do not promise universally bounded elapsed loss from a mere limit on the number of prefixes.

The proposed controller contract is deliberately about completed work:

    PlacementVector beginCohort();
    void recordArrival(int siteId);
    void recordActiveEvaluation(int filterId, boolean accepted, WorkDelta work);
    void completeCohort(RegionMeasurement measured);
    void abortCohort(Throwable failure);
    void close();

`beginCohort` returns the immutable selection for that cohort. Counters may accumulate while it runs, but `completeCohort` is the only point that may publish a pending alternative for subsequent work. `WorkDelta` and `RegionMeasurement` keep output rows, predicate invocations, physical access operations and active time separate. The final signatures may change during implementation if existing abstractions provide the same invariant more cleanly; the semantic, ownership and measurement contracts may not be weakened.
