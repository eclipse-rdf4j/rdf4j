# Query cache ownership and invalidation

LMDB query execution has several caches with different authorities. A compiled plan, a reusable cursor probe, an evaluation-local RDF value, and a compiled shape are not interchangeable objects. The safe question for every cache is: what identity is in its key, what scope owns it, what makes the value valid, and who releases it? The branch delta catalogued as Q12 covers current LMDB query cache additions and their consumers; store snapshot, value authority, and persistent-generation rules are linked as storage-owned validity constraints.

## Cache inventory

| Structure | Owner and key | Bound, invalidation, or release |
|---|---|---|
| `PlanValueCatalog` | Immutable compiled root; exact-spelling structural `NativeValueKey`. | Plan-lifetime constants only; no store mutation invalidation is needed because it contains the plan's own constants, not dictionary IDs. The value identity contract is described in [storage values and records](storage-values-and-records.md). |
| Runtime-value table | One `NativeExecutionContext`; evaluation-local append-only values and canonical ordinals. Nested semantic roots share the query owner's byte budget but can own separate runtime ID tables. | Explicit `rdf4j.lmdb.runtimeValues.maxBytes` admission budget; default is derived from max heap. Close releases accounted pages and table data. IDs must not escape that evaluation. |
| Dictionary/value-resolution cache | One `NativeValueResolver` per evaluation/source/catalog; four-way set-associative cache keyed by exact spelling and `valueLookupScope()` identity. | 1,024 sets × 4 ways = 4,096 entries; dictionary hits and misses are valid only for the read-view token. Token mismatch bypasses the cached entry; evaluation close clears retained spellings. |
| Generic prepared step | Per evaluation's `NativeExecutionContext`, keyed by `GenericSubplanDescriptor` object identity. | One prepared step per descriptor in that evaluation; all generic islands share one query-scope evaluation context, so NOW and labeled BNODE state are stable in the evaluation and isolated between evaluations. Context close ends the lifetime. |
| Generic island replay/keyed results | Per plan, source, immutable base binding snapshot, and effective LATERAL occurrence/entry frame. | Replay buffers are one-materialization row lists; keyed memo admits at most 256 distinct `BindingSet` term-equality keys. The cap bounds keys only, not the retained rows or bytes. Buffers close with their occurrence/evaluation state. Non-repeatable or mapping-parameterized subtrees are not memoized in production. |
| Semantic native state | Per evaluation, keyed by the compiled plan object/equality key supplied by the operator. | Lazily created and released with `NativeExecutionContext`; used for operators whose mutable state must not leak from a reusable compiled plan into concurrent or later evaluations. |
| Fragment evaluator | Process-wide `FragmentCompiler` LRU by structural IR shape. | Fixed 512 entries; values contain executable shape only, never store IDs or query bindings. Eviction only causes recompilation. |
| Janino whole-stage kernel | Process-wide LRU by canonical code shape. Store IDs and plan-local IDs are forbidden in both key and generated source; binding-specific authorities arrive through `KernelContext`. | `maxEntries` defaults to 512 and has a minimum of one. The entry cap is the bound; there is no generated-byte cap in this service. Failed compilation stays cached until eviction, preventing retry storms; caller falls back to the interpreter unless strict failure is configured. |
| Java Class-File-API filter specialization | Process-wide LRU keyed by `(slotCount, readMask)`; actual filter is supplied at call time. | Defaults to 128 entries and 512 KiB generated bytes. Both entry and byte limits can evict; a single shape too large for the byte budget is removed and uses the interpreter. These are distinct from Janino's whole-stage kernels. |
| Path result memo | One eligible path join/cursor and path-plan/source identity; key is start ID plus direction. | Each memo has its own stored-value budget, default 1,048,576 values; refusal bypasses caching. Closing the memo clears its arrays and returns its reservation. The enclosing path cursor separately closes its retained probe and adjacency views. It is not a store-wide plan cache. |
| Leapfrog constant frontiers | One `LeapfrogPlan` execution; key is pattern index, resolved four-term scan key, streamed quad position, and count mode. | Prefix-independent immutable frontiers can be shared across parallel workers up to 8 Mi values total. It stops adding entries at the cap rather than evicting; prefix-dependent frontiers are only reused at the same search level for the previous resolved key. Plan execution close owns its probes and cache. |
| Left-join/OPTIONAL materialization | The relevant join cursor/operator; keys project the shared binding slots. | Eligibility and row/entry caps are specific to hash, replay, memo, or sweep form; no cache is shared across query executions. See [join strategies](query-joins-and-factors.md) and the dedicated controls in [configuration](query-configuration.md). |

The *source* owns longer-lived adjacency projections, CSF pages, store statistics, and their generation certificates. Query plans borrow such data only through a snapshot-valid `NativeProbe` view. Those objects are documented in [storage adjacency lifecycle](storage-adjacency-lifecycle.md); they are not an evaluation-plan cache and do not belong in a process-wide compiled-kernel key.

## Identity and invalidation rules

Native store IDs are meaningful only in a particular `idSpace()`; learned cost correction has a different persistent-store identity, and value lookup has an explicit read-view token. Do not substitute one for another. Existing `LmdbValue` inputs bypass the spelling cache and are validated by the store first. For ordinary values, a cache hit linearizes at the initial token read and exact token match. A miss can become a hit after a new value record is visible, so the resolver rechecks the token after store lookup and before publishing either a positive or negative cache entry; if authority changed, it does not publish a reusable answer.

The native value resolver first checks the store, then immutable plan constants, and only then interns an evaluation-local synthetic value. Lookup-only callers do not treat a runtime-interned value as a store/catalog hit. Exact spelling is preserved for language tags, datatypes, base direction, and nested triple terms; canonical ordinals used for local equality do not erase a returned value's original spelling. Eviction or disabling lookup reuse changes work but not ID identity.

Compiled `SlotPlan` and kernel shapes can be reused safely only when their keys are shape-only. They must receive sources, dictionaries, plans, constants, and entry bindings at bind/open time. The process caches store compiled evaluators/classes, not a bound query plan with old source IDs. The current source does not contain the historical `LmdbPipelinePlanCache`, `PackedDphypEnumerator`, `DetachedPlan`, or `FrontierStatistics` APIs; do not implement against those names without a new source change.

## Generic island cache distinction

There are three separate states that are easy to collapse incorrectly:

1. **Prepared generic step:** one per descriptor identity per evaluation, sharing that evaluation's generic context and query scope.
2. **Independent replay buffer:** one drained result list for the effective base input, reused when the generic evaluation contract would materialize an independent child once. This preserves one UUID-like value for an independent volatile subtree across outer joins.
3. **Correlated result memo:** a production optimization only when `GenericTupleFacts` proves repeatability, no mapping-parameterized behavior, and no query-fatal-error raising. Its key contains only names the subtree observes, but `Value.equals` term equality defines `BindingSet` key equality. SPARQL value equality must not collapse keys.

`SERVICE`, paths, LATERAL, `TripleRef`, and tuple functions have mapping-parameterized semantics and are re-evaluated with their exact operator-entry frame; they are never routed through these buffers. The same prepared descriptor can occur beneath multiple LATERAL frames. Buffer identity therefore includes the effective entry frame/LATERAL occurrence; placing a replay list at the prepared-step cache would replay the first frame into later children. The 256-key bound does not bound bytes in any retained list. These results are not currently governed by `LmdbQueryMemoryManager`; see [memory and result lifecycle](query-memory-and-result-lifecycle.md) before growing them.

## Diagnostic counters are not plan caches

Some process-wide `AtomicLong` counters record opens, cache activity, or codegen metrics. A name such as `SHAPE_OPENS` describes telemetry, not reuse. Likewise adjacency access evidence is a store-scoped fixed primitive table, and cost-model posteriors are separate learned estimates. The [optimizer/statistics](query-optimizer-and-statistics.md) and [cost-learning](query-cost-learning-and-adaptation.md) guides explain those data owners and persistence separately.

## Extension checklist and source contracts

Before adding a cache, state its identity domain and prove that each key component covers every observable dependency. For data tied to a generation, include or validate the owning source/read-view token. Define what happens on budget refusal (stream, recompute, or decline), whether concurrent misses duplicate work, how a failing creation is removed, which scope closes it, and whether its retained bytes are included in a ledger. Never keep a mutable cursor or lease in a reusable plan/cache entry.
