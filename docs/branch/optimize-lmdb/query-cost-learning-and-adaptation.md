# LMDB query cost learning and adaptation

The cost model supplies dispatch evidence, not a semantic requirement. Each query can still use the stable strategy policy when there is no comparable price, and the adaptive trial system is separate from ordinary candidate execution. This guide describes the current machine/store hierarchy and its guarded adaptation paths; it reports no measured performance result. The branch delta catalogued as Q11 covers adaptive LMDB costing, observations, probes, and hedges; ordinary strategy ordering and execution semantics are baselines, not claims of measured benefit.

## What is observed

`LmdbNativeCostEstimate` identifies one physical variant, feature counts, predicted work, query shape, and structural uncertainty. `LmdbNativeCostObservation` is attached to an opened proposal and records whether it completed, was truncated by a consumer slice, was cancelled/censored as a probe, or declined. The model only learns from an outcome that has the needed comparable data.

The model has two scopes:

| Scope | Owner and learned information | Why it is shared at that scope |
|---|---|---|
| JVM-wide machine model | `LmdbNativeMachineCostModel` learns feature-to-time coefficients and uncertainty over strategy work features. | Common hardware/JVM factors can cancel when comparing same-lane candidates. |
| Per persistent store | `LmdbNativeStoreCostModel` keeps exact-variant feature-ratio corrections, hierarchical runtime posteriors, latest complete timings, workload regime, change detector, probe safety ledger and scheduler. | Store/data shape and its derived-statistic generation affect work and observed latency. |

Predictions use a residual lane when the machine model can price the feature vector; it learns runtime residual over that model. A direct lane learns log runtime itself for arms without comparable feature pricing. With neither features nor timing, a candidate has an `ORDINAL_ONLY` price: it remains eligible by stable preference, not a fabricated cross-candidate time. As measurements arrive the model can separate the arms. Common global/family uncertainty is modeled as shared and cancels pairwise; exact-arm and structural uncertainty do not.

Completed runs train machine coefficients, feature-count ratios and latency posteriors. A full, non-probe drain additionally updates the latest-observed timing ledger used for that query shape. `LIMIT`-truncated work can train a weighted posterior but is not a whole-query latest timing. Probe deadline censoring contributes only a right-censored lower bound on latency because final work-feature counts are unknown. A refused or failed opener does not become a completed timing sample.

## Regime changes and confidence

Store-scoped predictions are tagged with a regime/epoch derived from the data and execution context, including store generation, adjacency generation and codegen readiness. The change detector can bump the epoch when residual evidence indicates a sustained shift. Old observations remain bounded/decayed evidence rather than being mistaken for current exact behavior. An epoch change invalidates stale in-flight probe callbacks and makes previous scheduler cooldowns probe-eligible where the source says so.

The posterior is hierarchical: global lane/regime, family/shape/lane/regime, and exact variant/lane/regime levels. Variance floors keep confidence from becoming infinite; priors let the hierarchy price new variants while preserving uncertainty. Exponential aging lowers old precision, and an Huber clip limits the influence of one large miss. A latest observed complete time can replace a variant's current central expected time for its query shape; it does not erase the broader hierarchy or its uncertainty.

Ordinary adaptive selection first considers static specialization order and comparable costs. A cold static work interval may veto an unmeasured arm only when the rival interval is more than a factor of 256 below it; measured arms are not discarded by that cold-only rule. Cold-start rescue generally requires five completed exact measurements for a rival; native IR tiers qualify after one completed exact measurement. Censored evidence alone satisfies neither floor. Otherwise the hierarchy uses its 99% pairwise latent-displacement test with shared-component cancellation. If the test does not establish displacement, the stable policy remains. These are arbitration rules; they are not runtime-speed claims.

## Bounded probes, censoring and hedges

An adaptive probe is a private trial of a rival against a retained incumbent, admitted only at dispatch sites that register a harness capable of draining/discarding trial output. The trial deadline is derived from the incumbent predicted runtime and configured gamma, then capped. Probe selection considers probability of beating the displacement margin, expected benefit/information value, deadline utility, query cap, spacing, cooldown/single-flight state and safety-credit reservation. Trial output does not become query output. Completion updates exact observations; timeout records a censor. An overshoot can quarantine an arm because it demonstrates poor cancellation behavior at that shape.

Each persistent-store cost model owns a bounded probe scheduler keyed by physical variant/regime/epoch (up to 4,096 exact variants) and a per-query probe counter inherited by child dispatch scopes. Normal incumbent completion earns safety credit; a probe reserves credit before opening and can create debt only for a mandatory first measurement or deadline overshoot. A missing harness, active flight, exhausted query limit, insufficient deadline, cooldown/quarantine, safety-credit denial or failed resource admission leaves ordinary ranking intact. Hedge concurrency permits are a separate process-wide pool, not part of each store's probe scheduler.

Hedges are separate from serial probes. A site must register shadow-context and winner-publication support. An incumbent can race a probe trial or a delayed backup against a slow normal winner; only one result stream is published. The global hedge permit pool is bounded, and a permit is released only when a losing arm exits. If there is no pool capacity or source snapshot for a sibling, a planned hedge degrades to the serial probe or normal dispatch. Normal-dispatch guards require a usable measured runner-up. This extra work changes latency and contention on the current query; it is not a general timeout wrapper.

## Persistence and retention

When a store has a data directory, the per-store model can persist to `cost-model.lncm` if `rdf4j.lmdb.costModel.persist.enabled` is not case-insensitive `false` (default on). The sidecar is versioned, fingerprinted, and CRC32C-checked. A load parses/validates the complete payload before publishing any state; corruption, incompatibility or read failure starts cold. Loaded precision is decayed by age and capped, so persisted data cannot arrive with unlimited confidence. The sidecar persists global/family/exact posteriors and scheduler cooldown state; it does not persist the safety ledger or the JVM-wide machine coefficients.

Evidence marks the sidecar dirty at completion/store hooks. Background writes are best-effort and are gated by both at least 64 changed observations and a 30-second minimum interval; store close may force the pending state. The snapshot is captured while learner state is locked, then encoding and file I/O run after those locks are released. This avoids file I/O during ranking or row loops. A store with no data directory has no sidecar owner and keeps learned evidence only in memory.

The per-store model map is weak-keyed by source/store identity, but model suppliers can refer back to that store, so the store lifecycle explicitly releases/persists the model on close. Exact variant storage is capped at 4,096 entries; machine coefficient state is process-wide and small. The current source does not have a separate persisted compiled-plan cache, detached plan cache, or `PipelinePlanCache`; do not conflate cost evidence with reusable query plans. Compiled-kernel and query-result cache scopes are in [cache and invalidation](query-plan-caches-and-invalidation.md).

## Configuration references

`rdf4j.lmdb.costCalibration.enabled` controls whether learned calibration influences dispatch (default true); `rdf4j.lmdb.costCalibration.record` controls recording (default true). `rdf4j.lmdb.costCalibration.explore` is a separate randomized work-calibration setting, default false; it is not the same as bounded adaptive probes. `rdf4j.lmdb.adaptiveProbe.enabled` and `rdf4j.lmdb.adaptiveHedge.enabled` default true, but site support, deadlines, query limits, credits and permits still gate execution. See [configuration](query-configuration.md) for exact thresholds/defaults and [arbitration](query-arbitration-and-explanation.md) for decision semantics.

The posterior knobs use the `rdf4j.lmdb.costModel.*` namespace and are read when the per-store model/configuration is created. Numeric values are plain numbers: variance/noise/displacement settings are in log-runtime space; age/cooldown/staleness settings are milliseconds. Invalid, non-finite, zero/negative or out-of-range values fall back to the source defaults. Probe/hedge controls are parsed into immutable configs for one arbiter/model instance; changing a property does not rewrite an active trial, cancel a running worker, or rebuild current query plans. The runtime property allowlist exposes boolean controls only.

## Illustrative lifecycle example (source-only)

Suppose the stable policy first chooses an interpreted route, and a supported dispatch site has an eligible compiled rival. The first execution may train the interpreted exact variant; an admitted compiled probe uses a deadline and private sink. If the compiled attempt finishes inside its deadline, its exact timing/feature evidence can affect later dispatches for a matching regime and variant. If it exceeds the deadline, the result is censored rather than extrapolating from partial work, and a severe/non-cooperative route may be quarantined. Neither event changes the rows already published to the caller. This is a source-only lifecycle illustration, not observed runtime evidence.
