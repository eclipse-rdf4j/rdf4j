## Query and storage ownership boundary

Query documentation owns the LMDB `evaluation/**` and `factor/**` implementation trees, including their test trees, the query-focused root-package classes below, and `LmdbRuntimeProperties` as the primary owner of query-engine controls. The integration guide cross-references the same registry for its wider server and Workbench exposure. The root-package assignment is based on each type's role in planning, execution, result materialization, configuration, or query-scoped memory. ## Cross-guide interactions and edge cases

- A classified algebra type is not proof that every transformed shape can compile: compilation, lowering, strategy eligibility, proposal selection, successful open, and execution are separate states. Root generic hosting can coexist with native fragments. Interior generic islands have distinct placement and width constraints; whole-plan fallback remains possible.
- Explain and force controls must report the selected or declined family precisely. A pre-output open/validation failure may allow another proposal or a generic fallback where the call path permits it; after the first result, switching implementations would risk duplicate or missing rows and must not be described as transparent fallback.
- Treat Service and other generic paths according to current compiler/census/runtime checks, not a historical kernel-coverage census or a stale class comment. In particular, current source includes native-capable tuple-function and LATERAL cases with safety-dependent decline paths; this does not imply complete coverage.
- Join order, binding guarantees, variable scope, bag semantics, deterministic ordering, expression errors, DISTINCT/REDUCED, and correlated input shape interact with strategy choice. The guides state the actual guard and fallback instead of generalizing a specialized path to all nesting forms.
- Store-backed statistics, value IDs, predicate summaries, adjacency pages, asynchronous rebuilds, and query source snapshots have different owners and lifetimes. Query docs describe only the planning/execution contracts; durable formats, publication, transaction pinning, and shared memory charging belong to `storage-overview.md`, `storage-transactions-and-async-writes.md`, `storage-value-overlay.md`, `storage-csf-format.md`, and `storage-adjacency-lifecycle.md` as applicable.
- Source reasoning can describe asymptotic work, allocations, retained structures, and materialization points where the implementation establishes them. This inventory infers no present-day throughput, latency, universal native coverage, or JVM-compilation claim without measurement evidence.
