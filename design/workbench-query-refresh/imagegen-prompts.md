## A — Restrained refresh

Use case: ui-mockup. Create a high-fidelity realistic desktop UI design prototype for the RDF4J Workbench query page. Input image 1 is a reference for existing product identity, labels, feature inventory and layout, NOT a request to reproduce the dated styling. Design an incremental Tailwind-inspired refresh with system sans-serif typography and monospaced query/table values, white/light-neutral surfaces, restrained 1px borders, consistent 4/8px spacing rhythm, 6px corner radii, RDF4J orange as the single accent, strong accessibility contrast. Keep the original rdf4j / workbench identity and left navigation with server/repository, Explore, Modify and System sections. Keep repository context in the top header. Main page remains Query Repository, SPARQL editor followed by query controls and embedded Query Results below. Results are a real data table with columns s, p, o, plus download format, Download, results per page, previous/next, and show datatypes controls. Existing query actions Execute, Explain Query, Clear, Save Query and query name remain available, with limit, timeout, include inferred and save privately options. Use meaningful sample SELECT query and RDF terms. Do not add metrics, charts, artificial status pills, AI controls, new features, tabs between results and explanation, giant typography, excessive cards, decorative gradients, floating shadows, or marketing text. The prototype should look like a practical incremental redesign of the provided software. Flat frontal screenshot, desktop landscape approximately 1440x1100, entire workspace readable, no device frame. Concept A, restrained refresh: preserve existing vertical order and conventional navigation. Compact white brand/repository header 72px high, pale slate left nav ~190px with Query selected by a pale orange row and thin orange indicator. Main content uses 24px gutters and a 28px heading. Editor is white with a subtle border, 240px tall. Under it, put limit, timeout and checkboxes in one compact row, then Execute as solid orange with secondary Explain Query/Clear/Save Query actions in a clean aligned row. Results below form one continuous white work surface, compact control toolbar and readable table separated by subtle rules, no nested-page appearance. Use s p o examples with urn:subject, urn:predicate, literal values. This should be the safest least disruptive layout.
