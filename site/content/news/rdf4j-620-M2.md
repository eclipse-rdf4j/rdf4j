RDF4J 6.2.0 Milestone 2 is now available for download. This preview brings a redesigned Workbench and Graph Explorer,
new SPARQL functions, and query and LMDB improvements. This announcement covers the major changes in both Milestone 1
and Milestone 2 of the upcoming 6.2.0 release.

These are preview builds and are not yet feature-complete. We welcome your feedback as we prepare the final release.

<!--more-->

## Highlights

- **Workbench:** A responsive redesign brings light and dark themes, accessibility improvements, and more flexible
  controls. The new [Graph Explorer](https://github.com/eclipse-rdf4j/rdf4j/issues/6191) lets you explore query results
  and expand resources visually, switch between views such as a table or map, and retain the graph in your browser.
  See also the [Workbench redesign](https://github.com/eclipse-rdf4j/rdf4j/issues/6071).
- **Query performance:** The M1 join optimizer favors connected joins, while M2 adds scope-aware filter placement and
  UNION pruning, adaptive filter placement, and faster SHACL class validation for large class hierarchies
  ([join planning](https://github.com/eclipse-rdf4j/rdf4j/issues/5906),
  [filter and UNION optimizations](https://github.com/eclipse-rdf4j/rdf4j/issues/6189),
  [adaptive placement](https://github.com/eclipse-rdf4j/rdf4j/issues/6100),
  [SHACL](https://github.com/eclipse-rdf4j/rdf4j/issues/6139)). A separate
  [experimental query optimization profile](/documentation/reference/configuration/#base-sails) is configured per
  repository and remains disabled by default.
- **LMDB:** Storage and query work improves transaction handling, recovery, and read performance. An
  [offline bulk loader](https://github.com/eclipse-rdf4j/rdf4j/issues/6171) creates new repositories and reports
  loading and indexing progress. Direct-adjacency indexes and
  [native query execution](https://github.com/eclipse-rdf4j/rdf4j/issues/6169) are separate, opt-in accelerators;
  unsupported native query shapes fall back to the shared evaluator.
- **SPARQL:** The new [extension-function library](https://github.com/eclipse-rdf4j/rdf4j/issues/6193) includes
  functions for mathematics, strings, dates, JSON, aggregates, and windows. Correctness fixes cover named-graph and
  subquery scope, zero-length paths, SPARQL 1.2 reifier syntax, and FedX blank-node joins
  ([GRAPH](https://github.com/eclipse-rdf4j/rdf4j/issues/514),
  [paths](https://github.com/eclipse-rdf4j/rdf4j/issues/6153),
  [reifiers](https://github.com/eclipse-rdf4j/rdf4j/issues/6087),
  [FedX](https://github.com/eclipse-rdf4j/rdf4j/issues/6158)).
- **Tracing and cancellation:** M1 added opt-in [OpenTelemetry tracing](/documentation/programming/observability/)
  for repository operations and HTTP requests. M2 adds HTTP query cancellation; Workbench can cancel a running
  non-transactional query while keeping results already received. See
  [cancelling long-running queries](/documentation/tools/server-workbench/#cancelling-long-running-queries).
- **RDF input and output:** M1 added writer settings for serializing RDF 1.2 data as RDF 1.2 Basic or RDF 1.1, and
  expanded automatic decompression of RDF inputs in Server and Workbench, including nested TAR and ZIP archives
  ([output compatibility](https://github.com/eclipse-rdf4j/rdf4j/issues/5949),
  [input formats](https://github.com/eclipse-rdf4j/rdf4j/issues/6004)).
- **Security:** Spring Boot Server and Workbench bind to loopback by default. M2 adds browser request-integrity checks,
  redacts built-in repository passwords from public configuration views, and disables the Server logging page by default.
  The upgrade notes below describe settings and client changes that may be needed.

## Upgrade notes

- **LMDB format:** Existing 6.1 and M1 stores use format 2 and can be opened by M2 without conversion. New M2 stores
  use format 7, which 6.1 and M1 cannot read. To move data back to an older release, export RDF with M2 and import it
  into a fresh store. Unreleased experimental formats 3–6 must be exported using the version that created them and
  imported into a new store. See the [format change](https://github.com/eclipse-rdf4j/rdf4j/pull/6307).
- **Server and Workbench:** Set `server.address` explicitly if the Spring Boot listener needs remote access. Custom
  clients that submit changes through Workbench need a session token, and reverse proxies must forward the public
  scheme, host, and port; see [browser request integrity](/documentation/tools/server-workbench/#browser-request-integrity).
  The [Server logging page](/documentation/tools/server-workbench/#logging-configuration) requires explicit opt-in and
  access protection. Public configuration reads redact built-in HTTP repository and Elasticsearch passwords; changing a
  protected destination can require supplying the credentials again.
